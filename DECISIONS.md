# Решения

Что решили, какие были альтернативы и почему выбрали именно это.

## 2026-10-02. Корпус (что индексируем): книги по трейдингу, а не спецификация MCP

- **Решение:** индексируем книги по трейдингу. Сервис будет отдельным и поможет продукту crypto-analyst.
- **Альтернатива:** индексировать документацию протокола MCP, как в исходном плане. Речь только о том, *что* лежит в индексе. *Как* сервис отдаёт результаты — это отдельное решение: HTTP `/search` и MCP-сервер, через который crypto-analyst будет вызывать поиск как инструмент (неделя 4).
- **Почему:** проект получается не учебным, а полезным для моего продукта.
- **Цена:** книги защищены авторским правом. Они лежат в `data/`, а `data/` в `.gitignore`. В публичный репозиторий и в CI они не попадут, см. «Открытые вопросы».

## 2026-10-02. `Chunk` — frozen dataclass, `heading_path` — tuple

- **Решение:** `@dataclass(frozen=True)`.
- **Альтернативы:** `dict` или Pydantic-модель.
- **Почему:**
  - Чанки создаёт наш собственный код, проверять типы при запуске не нужно. Pydantic нужен на границах: API и внешний JSON.
  - `frozen` делает объект неизменяемым и хешируемым, поэтому чанки можно класть в `set` и использовать как ключи `dict`. Это пригодится для дедупликации результатов поиска.
  - `tuple` вместо `list`, потому что list не хешируется, а `frozen` замораживает только сам объект, не вложенный список.

## 2026-10-03. Режем по заголовкам и храним полный путь

- **Решение:** чанк — это текст между заголовками. У каждого чанка есть полный путь: глава › раздел › подраздел.
- **Альтернативы:**
  - фиксированный размер в токенах;
  - хранить только последний заголовок.
- **Почему:**
  - Заголовки — это границы по смыслу, которые расставил сам автор. При фиксированном размере разрез попадает на середину мысли.
  - Полный путь даёт три вещи: ссылку на источник для crypto-analyst, различие между одинаковыми названиями («Summary» встречается в каждой главе) и контекст для поиска (название главы несёт смысл для всех её разделов).
- **Цена:** разделы получаются очень разного размера, см. «Открытые вопросы».

## 2026-10-06. EPUB читаем как HTML, а не через pymupdf4llm

- **Решение:** открываем EPUB как zip-архив. Названия глав берём из оглавления (`toc.ncx`), HTML глав переводим в markdown через `markdownify`.
- **Альтернативы** (замерено на книге Murphy, _Technical Analysis of the Financial Markets_):

  | Способ                                   | Результат                                                      |
  | ---------------------------------------- | -------------------------------------------------------------- |
  | pymupdf4llm, заголовки по размеру шрифта | глав нет, разделы стали `###`, в заголовках мусор `**` и `<u>` |
  | pymupdf4llm, заголовки из оглавления     | 6 заголовков на всю книгу, почти все неверные                  |
  | HTML + оглавление                        | глава › раздел › подраздел на своих местах, 423 чанка          |

- **Почему:** издатель разметил книгу смысловыми тегами (`<h1>` — раздел, `<h2>` — подраздел), а размер шрифта — только догадка. Названия глав внутри страниц — картинки, текстом они есть только в оглавлении.
- **Цена:** способ работает только для EPUB. Для PDF тегов нет, там вернёмся к pymupdf4llm.

## Открытые вопросы

- 37 чанков из 423 длиннее 3000 символов, это больше лимита учебной модели в 512 токенов. Глоссарий целиком лёг в один чанк в 18 000 символов. Длинные разделы нужно дорезать по абзацам при любой модели: вектор одного огромного куска размыт, а в ответ аналитику уходит лишний текст.
- **Модель эмбеддингов для прода.** Учимся на локальной `multilingual-e5-small`, у неё 512 токенов. Для прода рассмотреть модели с длинным окном и лучшим качеством. Выбирать по метрикам на golden set (неделя 4), а не по описанию. Код должен позволять заменить модель.
- **Корпус для публичного репозитория и CI.** Боевые книги туда нельзя. Нужен небольшой корпус, который разрешено публиковать, чтобы README-демо и evals в CI работали. Кандидаты — книги из общественного достояния (Wyckoff 1910, Lefèvre 1923). Боевой корпус для crypto-analyst — отдельно, лучшие книги, хранятся локально.
- Названия разделов набраны капсом («PHILOSOPHY OR RATIONALE»). В оглавлении они записаны нормально.
